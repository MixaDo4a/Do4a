# Перенос конструктора и каталога в онлайн

## Цель

Конструктор и приложение должны работать с одними данными из любого браузера и устройства. Фото и видео хранятся в объектном хранилище, а не в браузере.

## Целевая схема

- **Vercel** — публикация Next.js приложения.
- **Postgres** — акции, меню, продукты, группы допов, допы и связи.
- **Object Storage** — фото и видео с публичными или подписанными URL.
- **API** — серверные маршруты Next.js для чтения и изменения данных.
- **Авторизация** — доступ к конструктору только владельцу; приложение читает опубликованный каталог.

## Порядок переноса

1. Зафиксировать модель данных и не использовать `localStorage` как источник истины.
2. Создать таблицы акций, меню, продуктов, групп допов, допов и связей продукта с группами.
3. Создать API каталога и API конструктора.
4. Перенести загрузку файлов в object storage через presigned upload URL.
5. Перенести текущие локальные записи в базу и загрузить медиафайлы отдельно.
6. Переключить приложение на API и удалить тестовые fallback-данные.
7. Переключить конструктор на API, затем проверить создание, редактирование, удаление и публикацию.
8. Добавить проверку размера, типа и статуса загрузки медиа.
9. Собрать production-версию и проверить её на Vercel.

## Правило переходного периода

`localStorage` и IndexedDB используются только для одноразовой миграции уже созданных локальных данных. После успешной миграции приложение не записывает туда каталог или медиа.

## Что нужно для публикации

- проект базы данных;
- bucket для медиа;
- переменные окружения Vercel для подключения к базе и storage;
- отдельная роль администратора конструктора.
